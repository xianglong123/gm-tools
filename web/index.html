格式与兼容

联调时 90% 的坑都在格式和填充上，这里集中说明各算法的密钥格式、模式差异与常见踩坑点。

SM2 公钥

  • 04 + X + Y（130 hex）：标准未压缩格式，BouncyCastle、Hutool 默认输出
  • X + Y（128 hex）：很多网关和 SDK 会省掉 04 前缀，本页会自动补上
  • 02/03 + X（66 hex）：压缩格式，本页直接支持

SM2 密文顺序

  • C1C3C2：GB/T 32918 推荐、BouncyCastle 默认，新项目优先用这个
  • C1C2C3：老版本硬件加密机、部分国密网关在用
  • 顺序选错不会报错，只会解出空串或乱码——所以本页把选项放在了密钥区最显眼的位置

SM4

  • 密钥固定 16 字节；ECB 不需要 IV，CBC 必须 16 字节 IV
  • 填充默认 PKCS#7，与 Java Sm4Util、国密网关一致
  • 无填充模式只接受 16 字节整数倍的 hex 明文，用于验证标准向量
  • 本页输出的密文为 hex；base64 密文可直接粘贴到解密框，会自动识别

通用算法（AES / DES / RSA / 摘要）

  • AES 支持 ECB / CBC / CTR / CFB / OFB / GCM，密钥 128 / 192 / 256 位；GCM 走浏览器原生 WebCrypto，密文尾部自带 16 字节认证标签
  • CTR / CFB / OFB / GCM 是流模式，不需要填充；ECB 相同明文块会得到相同密文块，生产环境不推荐，仅作兼容
  • 3DES 密钥 16 或 24 字节；DES 已不安全，保留只是为对接老系统
  • RSA 支持 PKCS#1 v1.5 与 OAEP-SHA256 加密、PKCS#1 v1.5 与 PSS 签名；PKCS#1 / PKCS#8 / SPKI 三种 PEM 自动识别，不用自己转换
  • RSA 只能加密短数据（2048 位最多约 245 字节），长内容请用 AES 加密正文 + RSA 加密密钥
  • 摘要支持 SM3 / SHA-256 / SHA-384 / SHA-512 / SHA-1 / MD5，均可叠加 HMAC；SHA-1 与 MD5 只作兼容，不要用于新系统

关于这个工具

  • 全部运算在浏览器里完成，请求里没有任何密钥或明文，服务器只返回静态页面
  • 无后端、无数据库、无账号、无 cookie；关闭或刷新页面，输入内容即消失
  • 算法实现为 sm-crypto 0.3.13 + crypto-js 4.2.0 + 浏览器原生 WebCrypto，全部本地引入，不走 CDN
  • 国密部分已用 GB/T 32905 / 32907 标准向量校验，AES 已与 openssl 交叉验证
  • 仅供调试与学习使用，生产环境的密钥管理请交给 HSM / KMS
