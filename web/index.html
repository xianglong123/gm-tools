数字信封

长文本用 SM4 加密，SM4 密钥再用 SM2 公钥加密——这是国密应用里最常用的组合（信封加密）。一次可以处理任意长度的文本。

加密 明文 → 信封

随机生成 SM4 会话密钥 + IV，每次结果都不同

解密 信封 → 明文

用错私钥会提示解封失败，不会输出乱码

格式与兼容

国密联调 90% 的坑都在格式上，这里集中说明。

SM2 公钥

  • 04 + X + Y（130 hex）：标准未压缩格式，BouncyCastle、Hutool 默认输出
  • X + Y（128 hex）：很多网关和 SDK 会省掉 04 前缀，本页会自动补上
  • 02/03 + X（66 hex）：压缩格式，本页直接支持

SM2 密文顺序

  • C1C3C2：GB/T 32918 推荐、BouncyCastle 默认，新项目优先用这个
  • C1C2C3：老版本硬件加密机、部分国密网关在用
  • 顺序选错不会报错，只会解出空串或乱码——所以本页把选项放在了密钥区最显眼的位置

SM4

  • 密钥固定 16 字节；ECB 不需要 IV，CBC 必须 16 字节 IV
  • 填充默认 PKCS#7，与 Java Sm4Util、国密网关一致
  • 无填充模式只接受 16 字节整数倍的 hex 明文，用于验证标准向量
  • 本页输出的密文为 hex；base64 密文可直接粘贴到解密框，会自动识别

关于这个工具

  • 全部运算在浏览器里完成，请求里没有任何密钥或明文，服务器只返回静态页面
  • 无后端、无数据库、无账号、无 cookie；关闭或刷新页面，输入内容即消失
  • 算法实现为 sm-crypto 0.3.13（本地引入，不走 CDN），已用 GB/T 32905 / 32907 标准向量校验
